# ChatGPT copy/paste plan import

Home and Plan gain Import a plan. The shared sheet provides a copyable prompt containing only the chosen semester ID/date bounds, module codes and Singapore date. No account email, token, saved task list or credentials are put in the prompt. User supplies their plan to ChatGPT separately and pastes its JSON reply. Nothing calls an AI API or requires an MCP connection.

Envelope: {format: "ntu-study-plan-v1", semesterId: "selected id", tasks: [...]}. Required task fields date/module/title; optional minutes/startTime/endTime/notes/priority. 1-100 rows and at most 200k input characters. Untimed tasks stay flexible. End minus start derives planned minutes; otherwise unknown duration defaults visibly to 30 minutes for review. Invalid dates/module/time ranges/unknown fields are flagged and excluded. Existing/repeated same-day same-module same-title/same-time tasks are skipped, regardless of duration/notes/completion differences; no edits are inferred. Intentional duplicates must be distinguished by title/time or added normally.

Preview performs no writes. User checks rows and explicitly presses Add selected tasks. This is a user-reviewed creation flow using the existing source:user insert pipeline, not an autonomous external ChatGPT/MCP change. Account/semester/config/input changes invalidate the preview. Duplicates are checked again immediately before insertion. Saving uses the existing app sync/status/errors; no direct database calls or write retries. No existing records are edited or deleted. This does not repair the separate OAuth connection.

Limits: JSON-only import; no free-text parsing/AI service, automatic edits, recurring rules, assessments/classes or overnight single-task sessions. Existing same-day same-title matching can skip an intentionally repeated flexible task. Clipboard has manual-select fallback. The preview batch is staged in memory then passed through existing cloud saving; the legacy backend does not provide a transactional multi-task import or server idempotency keys. Wait for saved status; if interrupted, reload and preview again so duplicate checks use reloaded data.
