# Immediate manual task actions and 7-day app Trash

Manual task edits and rescheduling now apply through the existing save pipeline without creating Inbox proposals. Manual task deletion immediately moves the task into existing recoverable recordTrash and offers an Undo toast; no delete confirmation or approval entry. Settings > Task Trash > Open Task Trash shows deleted tasks across the signed-in workspace's semesters, with original module/date, expiry time and Restore. Restore returns the original task ID/content (including notes, priority and optional times). Existing other record/file Trash remains intact.

Retention is exactly 7 x 24 hours from deletion timestamp. Expired task entries disappear from the app Trash and existing deleted-items manager and cannot be restored via the app restore/Undo methods. Time is checked whenever read/restored and approximately every minute while the Task Trash sheet is open. Reload never resets deletion time. This is an application restore window, NOT permanent server-side deletion: soft-deleted database records, metadata copies and backups are retained; no scheduled backend purge or SQL job is installed. A server-enforced deletion/privacy guarantee would require a separately reviewed backend job. Legacy task entries with missing/invalid deletion dates remain recoverable rather than being guessed expired. Files/classes/assessments/academic years retain their current policies. Existing pending proposals are not automatically applied or removed.

External ChatGPT/MCP app-pipeline proposals and other existing schedule proposals retain their approval policy. The running legacy MCP adapter itself is unchanged; this feature does not add app-Trash linkage for deletions performed through that separate API. No database/schema/RLS/Edge Function/Auth0/NTULearn/credentials changes and no real record edits/deletes during development.
